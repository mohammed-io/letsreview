# github_canvas_ui

## Status: completed (20260514155037)

## Context
Current letsreview UI renders diffs on Canvas but uses a custom orange-heavy shell and spacing that does not feel like GitHub. User wants to open the app against `~/Projects/email-client`, keep Canvas rendering, and leave deeper color iteration for later.

## Value Proposition
Make the product easier to recognize and scan by matching GitHub's dark UI structure: restrained neutral surfaces, blue focus/action color, green/red diff semantics, dense file navigation, and a code-review toolbar that feels familiar.

## Alternatives considered (with trade-offs)
- Full GitHub clone in DOM: highest fidelity for layout and accessibility, but violates Canvas-rendering constraint.
- Keep current shell and only recolor Canvas: fastest, but leaves large UI mismatch in sidebar, toolbar, and panels.
- Adopt GitHub-like shell plus Canvas diff token palette: best current fit, preserves architecture while improving visual quality.
- Add design-system component layer: cleaner long-term, but too much abstraction for this small static app.
